PROJECT 03 / DATA ENGINEERING

Automated ETL Pipeline.

A modular workflow for extracting, transforming, validating, and loading spreadsheet-based datasets.

RreadxldplyrDBIPostgreSQL
01 / OVERVIEW

Project overview

A modular ETL workflow designed to move spreadsheet-based source data into structured PostgreSQL tables through repeatable processing steps.

02 / CHALLENGE

The challenge

Manual spreadsheet processing can require repeated cleaning and formatting work. Inconsistent whitespace, date formats, column names, missing values, and invalid types can cause loading failures or inconsistent database records.

03 / APPROACH

Technical approach

The workflow separates extraction, transformation, validation, and loading into distinct scripts. This makes each stage easier to test, troubleshoot, and maintain.

  • Extract source worksheets using R and readxl.
  • Normalize column names, whitespace, and non-breaking spaces.
  • Standardize date and numeric fields.
  • Validate required fields and target data types before loading.
  • Load validated records into PostgreSQL using DBI-compatible tools.
04 / CONTRIBUTION

My contributions

  • Structure the ETL process into modular scripts.
  • Implement data cleaning and standardization rules.
  • Build pre-load validation checks.
  • Handle database loading and record replacement procedures.
05 / OUTCOME

Outcome & considerations

The modular design makes the data preparation workflow more repeatable and easier to troubleshoot. Scheduling, monitoring, transaction strategy, and recovery behavior should be documented for each production deployment.
